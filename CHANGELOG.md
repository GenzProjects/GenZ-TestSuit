# Changelog

## [1.0.1] - GenZ-TestSuit-v1.0.1 (2026-11-20)
- Targets **GenZ Ads v1.33** (`AdsScripts-GenzAds`).
- **v1.33 scene layout:** an Ads-object script that isn't on the Ads object (v1.33 puts FirebaseManager + RemoteConfigManager and unityInApp on their own objects) is looked for in the SDK scenes, inactive objects included: found there = pass for v1.33 (fields and IDs still checked, Auto Apply still works), warning for v1.32. "Object is active" passes for an inactive object ConsentManager starts (its Analytical / Monetization Objects), e.g. UmpManager.
- **Window:** no more empty gap above the results when the Auto Apply or Fix GA Ad Formats bar is shown.
- **Checks follow the project's GenZ Ads version** (v1.32 or v1.33), found from the scripts' `// GenzMonetization-v…` line, else `Release.txt`, else GenZLog / RemoteConfigManager present = v1.33, else v1.32 (`GenZCodeChecks.DetectAdsVersion`, shown in Environment and step 4). From a v1.33 project, the v1.33 features are required (fail when missing): version line, RemoteConfigManager / GenZLog / ConsentManager (`codeChecks.requiredScriptsV133`), consent screen in the first scene, App Open skip set and cleared for purchases and the review, Remote Config fetch reported, UMP waiting for the tracking prompt. For a v1.32 project they're only reported (info). The APK suite reads a build with no `[GenZ]` lines as a v1.32 build: the checks that need those lines are skipped, Firebase / GameAnalytics / Taichi events / crashes still run.
- **iOS IDs from the iOS tabs:** with the iOS build target, the IDs are compared with `IOS Games ID's` and `IOS MAX Ids` (config `iosSheetTabs`, Config v12), the shared MAX SDK key is read from `Android Max ID's` (Key Only), and the settings rules read the iOS fields (Google Mobile Ads / AppLovin iOS App ID, GameAnalytics iPhone keys). Store links use the game's iOS store. The Game list shows the iOS apps.
- **Rate Us link** (step 1, Store links): must open the game's own store page: Android its package's Play page, iOS the sheet's `App ID` on the App Store. Another game's page fails, and so does a Play link in the iOS build or an App Store link in the Android build. A game using only the native review dialog gets an info row.
- **Menu:** **GenZ → Run Editor Test Suit** is removed; open **GenZ → Test Suit** and use the window's run button.
- **Android and iOS:** with the iOS build target, step 2 skips the Android-only checks and runs the iOS ones: GoogleService-Info.plist (bundle ID), MAX adapters by iOS pod, App Tracking prompt text (NSUserTrackingUsageDescription) and SKAdNetwork sample files. Android Player Settings are skipped on iOS. The **APK and Deep tabs are hidden on iOS** (they use adb, logcat and APK files; Android only); the release guard reports the Android test define as info there.
- **Consent screen and startup** (step 2): ConsentManager in the first scene, its screens and objects set, ad objects inactive until consent, Firebase present, next scene valid and not itself, Accept button wired and tappable, and no button the player can tap calling a missing method. A button fully covered by another element drawn on top (e.g. an old `PP` left under its replacement `PP_Button`) can't be tapped: its broken call is info ("hidden leftover"); a covered Accept button fails.
- **Platform-only code** (step 4): iOS-only code (App Tracking) inside `#if UNITY_IOS`, Android-only code (Play Review) inside `#if UNITY_ANDROID`, so neither build breaks. **Startup order** (step 4): the Remote Config fetch is reported on success and failure when a screen waits for it; on iOS, UMP waits for Apple's tracking prompt.
- **Auto Apply** now writes the sheet's Taichi 2.0 count into the code when a game has no `RemoteConfigManager` Inspector field (e.g. `{ "custom_imp", 50L }` in `FirebaseManager`). Before, it was checked but never applied.
- **Player Settings, Unity 6:** Minimum API Level 24 or 25 passes (`minSdkUnity6`), and **Show Splash Screen** must be off (`showSplashScreenUnity6`). Older Unity is unchanged.
- **GameAnalytics ad revenue formats** (step 2): the AdMob integration (`GAAdMobIntegration.cs`) must send the same ad format strings as MAX (`GAMaxIntegration.cs`), e.g. `INTER` not `INTERSTITIAL`, `REWARDED` for rewarded, or GameAnalytics shows one format as two. New **Fix GA Ad Formats** button corrects them. Also checks the GA ad network defines and the `GameAnalyticsILRD` subscribe calls.
- **Ad scripts version** (step 4): every script in `AdsScripts-GenzAds` must start with the same `// GenzMonetization-v1.33` header. Mixed versions or a missing header fail; a game from before v1.33 (no headers) or an older version warns. Raise `GenZTestSuitInfo.AdsScriptsVersion` with each GenZ Ads release.
- **AppLovin MAX adapters** (step 2): every adapter in the studio list must be installed (BidMachine, Bigo Ads, Pangle, Meta, DT Exchange, Google AdMob, Google Ad Manager, InMobi, Mintegral, Smaato, Unity Ads, Liftoff/Vungle, Yandex, YSO Network, and the custom networks AdSurge and Helix / Voodoo ADN), IronSource must be removed (adapter, Mediation folder and IronSource / LevelPlay SDK), and any other adapter warns. Lists in the config: `integration.maxAdapters`, `forbiddenAdapters`, `adapterPattern`.
- **No App Open ad after a purchase or review** (step 4): the App Open ad must check `isPausedDuetoAd` (config `appOpenSkipFlags`); purchases and the in-app review must set it before opening the store dialog / review card, and clear it again a moment (real time) after the flow ends, including on failure and early exits. Otherwise an App Open ad shows on return, or a stuck flag skips the next real one. A missing set on the review fails; the rest warns, so v1.32 games still pass.
- **Store links: privacy policy and More Games** (step 1): every privacy policy and More Games link (buttons such as `ConsentManager.OpenPrivacyLink`, scenes, prefabs, script strings) must be the live store's links from the sheet's `Stors` tab (`Privicy Policy`, `Link`). The store is the games tab's last `Store Name` column (the live store). Another store's page, a Google redirect link (`google.com/url?q=…`), no `https://` or an empty link fails; More Games is only checked when the game has one. The whole project is scanned (every scene, prefab, ScriptableObject asset, Inspector text field and script outside the SDK folders); a wrong link in a file the build doesn't use is a warning. Auto Correct fixes links in the SDK scenes. Config v11 adds `Stors` to the Sheet Tabs.

## [1.0.0] - GenZ-TestSuit-v1.0 (2026-10-22; packaged 2026-10-29)
- **GenZ-EditorTestSuit** (first tab), four steps:
  1. IDs Check: every ad unit ID, app ID, SDK key and token against the studio Google Sheet, with Auto Apply and Auto Correct; keystore against the sheet.
  2. SDK Integration: SDK scene objects and settings assets, SDK files and Gradle setup, Android signing, and the Android Player Settings (Auto Graphics API off, no Vulkan, ES3.1 off, ES3.1+AEP and ES3.2 on, IL2CPP, ARMv7 + ARM64 only, minimum API 24, target API 36).
  3. Taichi: Taichi 1.0 / 2.0 switches, Inspector defaults and their revenue events.
  4. Ad Calling Scenarios: the ad code read statically (waterfall, vendor switch, banners, reloads, revenue, AdsGapTimer, Remote Config defaults).
- **GenZ-ApkTestSuit** (second tab, first version; not yet run on a phone): Build & Device, SDK Init, Analytics Events, Ads, Stability, read from logcat on a release build. Needs `GenZLog.cs` and its `[GenZ]` lines in the game's `AdsScripts-GenzAds`.
- **GenZ-DeepTestSuit** (third tab, first version; not yet run on a phone): Test / Release Environment and the phone's shake panel.
- Distributed as the Unity package `com.genz.testsuit` (git URL). The config is created in `Assets/GenZ-TestSuit/`, and the phone panel is installed from the package by Apply Test Environment.

## Releasing a new version
1. Raise `GenZTestSuitInfo.Version` in `Editor/GenZTestSuitConfig.cs`. The window title, its header and copied reports use it.
2. Change the first line of every `.cs` file in `Editor/` and of `Editor/Templates/GenZDeepTestPanel.cs.txt` to `// GenZ-TestSuit-v<version>`. The panel's first line is how projects know their installed panel is out of date.
3. Raise `version` in `package.json` (e.g. `1.1.0`).
4. Add an entry at the top of this file and of the changelog in `Documentation~/GenZ-TestSuit.md`.
5. Change the `#v…` tag in both install lines of `README.md` to the new version.
6. Commit, tag `v<package version>` (e.g. `git tag v1.1.0`) and push with `git push origin main --tags`. Games update by changing the `#v…` in their git URL.
7. Create the GitHub release for the tag, with this version's changelog entry and the install line as its notes: `gh release create v<package version> --title v<package version> --notes-file <notes.md> --latest`.
