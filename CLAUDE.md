# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"One Go Line Puzzle" — a Unity mobile (Android-first) draw-one-line puzzle game. The editor version is in `ProjectSettings/ProjectVersion.txt`: `main` is on **2022.3.62f2**, and the `v2.71-41-UnityEditor6` branch is migrating to **Unity 6000.3.12f1** (packages upgraded in `Packages/manifest.json`, TextMeshPro folded into `com.unity.ugui` 2.0.0). Where this file names `2022.3.62f2` paths (e.g. the Managed DLLs used for `dotnet build`), use the folder of whatever version `ProjectVersion.txt` says. Package `com.gps.onego.line.puzzle`; version is set via `bundleVersion` / `AndroidBundleVersionCode` in `ProjectSettings/ProjectSettings.asset` (currently 2.71, code 41). Git remote is `GenzProjects/And-OneGoLine`; each release gets a branch named `v<bundleVersion>-<versionCode>` (e.g. `v2.7-40`) off `main`.

## Code layout

Game code lives in only a few places — everything else under `Assets/` is third-party SDKs/asset kits (Adjust, AppMetrica, Firebase, GameAnalytics, MaxSdk, GoogleMobileAds, Dreamteck Splines, DOTween/Demigiant, NiceVibrations, 2DxFX, Epic Toon FX, etc.) and should not be modified:

- `Assets/Scripts/` — gameplay (`GamePlayScripts/`), shared managers (`Common/`), missions, rewarded-ad item scripts (`RewScripts/`), splash, tutorial, consent.
- `Assets/GameScripts/Basic/UiManager.cs` — the large per-scene UI controller (dialogs, level-complete flow, scene switching, settings toggles).
- `Assets/AdsScripts-GenzAds/` (unversioned folder name; the version, currently GenZ Ads v1.32, is in its `RELEASE.txt`) — the studio's shared monetization/analytics layer (MAX + AdMob ads, app-open ads, UMP consent, Firebase remote config, GameAnalytics/AppMetrica/Adjust wrappers, Unity IAP, in-app review). `GenZLog.cs` here writes the `[GenZ]` lines the APK Test Suit reads; keep its calls when updating these scripts.

## Architecture

**Scene flow:** `Consent` → `Splash` → the player's current level scene. Splash sets `GameManager.Instance.selectedLevel = GetLevelNumber()` and loads `GetLevelName(...)`. There is no main-menu/level-select scene in the build (UiManager still references `MainMenu`/`LevelSelection` scenes that don't exist — those paths are dead).

**One scene per level.** Each puzzle is a hand-authored scene (`Level_N.unity`). Play order is *not* the scene number: it's defined by the `levelNames` array in `Assets/Scripts/Common/GameManager.cs`, and `GameManager.totalLevels` controls the wrap-around back to index 0 after the last level. When adding/removing a level you must update `levelNames`, `totalLevels`, and Build Settings together. The wrap check (`selectedLevel >= totalLevels`, in `UiManager` and `RewSkipLevel`) compares against the 0-based index; currently `levelNames` has 113 entries but `totalLevels = 111`, so the last entries are never reached — verify the intended value before changing either. `ResetLevelsOrder()` can reorder levels from a Firebase remote-config JSON (`LevelData`), but that read is currently commented out in `RemoteConfigManager.LoadValues`. `DLevel_*` scenes are in the build but not in `levelNames` (unused/debug variants, driven by `DummyUI`).

**State:** `GameManager` is a plain C# lazy singleton (not a MonoBehaviour) holding session state (`selectedLevel`, `failCount`, `crossCounter`, `canShowHardLevel`, …) and wrapping all persistence, which is entirely `PlayerPrefs` (coins, unlocked level, hints, skips, cosmetics, plus many ad-hoc flag keys scattered across scripts). New persisted state should follow this `GameManager` + `PlayerPrefs` pattern rather than add a new persistence layer.

**Singletons:** MonoBehaviour managers use a `public static X instance` set in `Awake`. Persistent ones call `DontDestroyOnLoad` (`AdsManager`, `FirebaseManager`, `SFX_VFXManager`, `DataManager`, `MyVibrator`, `AdsGapTimer`, `RandomRewardManager`); per-level ones (`LevelManager`, `UiManager`) are re-created with each level scene (the UI comes from the `CanvasUi`/`UI` prefabs placed in every level).

**Core gameplay (Dreamteck Splines):** each level's shape is a set of `SplineComputer`s joined at Dreamteck `Node`s; each spline has a `TubeGenerator` (rendered line), and a `MySplineRef` (`isCompleted` flag + sample `splinePos` points).
- `PlayerInput` handles touch/mouse, picks the nearest spline on press, moves a `SplineProjector` with the finger, and on release checks completion — any release before every spline is completed = level failed, which reloads the scene.
- `ProjectorLineGenerator` (on the projector) does the line-drawing: it advances the `TubeGenerator` clip range as the finger moves and, in `OnTriggerStay2D` against node colliders, decides which connected uncompleted spline to continue onto and marks splines complete.
- `LevelManager` holds per-level references (`PlayerInput`, `Tutorial`, `Hint`, input bounds `minY`/`maxY`).
- Completion goes through `UiManager.LevelCompleteGenericFunction()`, which logs analytics, advances/unlocks the level, and decides on interstitials (gated by `AdsGapTimer` and remote-config values).

**Remote config / monetization knobs:** all of them are in `Assets/AdsScripts-GenzAds/RemoteConfigManager.cs`, the only per-game Remote Config file. It's a MonoBehaviour that goes on the ADs object (next to `FirebaseManager`); its values and methods are static. `FirebaseManager` is the same in every studio game: it passes `RemoteConfigManager.Defaults()` to `SetDefaultsAsync` before the first fetch, and calls `RemoteConfigManager.LoadValues(rc)` after each fetch + activate.
- Each key is a static field whose starting value is also its Remote Config default. Keys: `adtimer`, `adtimertwo`, `useSdkVendorSwitch`, `custom_rev`, `custom_imp`, `firstad`, `rewpopupfreq`, `bigbanner`, `rewcointest`, `showBrainBar`, `showRewOnHard`.
- Gameplay and UI code read the fields directly, e.g. `RemoteConfigManager.canShowBrainBar` toggles the progress bar vs. the "hard level" slider. The Taichi code in `FirebaseManager` reads `RemoteConfigManager.revenue_maxValue` and `impressionValue_ForRevenue`.
- The Taichi defaults are `[SerializeField]` Inspector fields: `taichi1DefaultRevenue` (`custom_rev`, USD) and `taichi2DefaultImpressions` (`custom_imp`, must equal the sheet's "Taichi 2.0 Default Values"). `Awake` copies them into the statics before `FirebaseManager` builds the defaults. Without the component, the values in the code are used.
- Load order: `Awake` sets the Inspector defaults. `Start` calls `LoadValuesFromSystem()`, an empty hook for the developer: it reads the values saved on the device last time (PlayerPrefs or a local JSON file). It runs before the fetch, so those values are used until then and also become the Remote Config defaults. After the fetch, `LoadValues()` sets the fetched values, and the developer saves them there for the next launch.
- A new key needs three things in that file: a field, its entry in `Defaults()`, and its read in `LoadValues()`.
- `LoadValues` writes the `[GenZ] RemoteConfig|values|…custom_imp=…` line the APK suite reads; keep its format.

The MREC is shown with `AdsManager.ShowMRECBanner/HideMRECBanner` (`BigBanner.cs` was removed). Every 5th level is a "hard level"; rewarded features (hint, skip, coins, unlocks) are in `Scripts/RewScripts/` and call `AdsManager.instance.ShowRewardedAd(callback)`.

**Analytics convention:** level events use 1-based names `"level_" + (selectedLevel + 1)` and are sent to both `GA_Aanalytics` (GameAnalytics) and `AppmetricaAnalytics`; keep both in sync when adding events.
